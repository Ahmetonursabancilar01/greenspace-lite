# Team Agreement & Definition of Done (DoD) — Individual Workflow

## 1. Individual Working Agreement & Discipline
Since **GreenSpace Lite** is developed as an individual project by a single developer (Ahmet Onur Sabancılar), the workflow is structured around personal accountability, strict version control discipline, and time management:
- **Version Control Discipline:** Every feature, bug fix, or documentation update must be developed in an isolated manner, committed with meaningful messages, and pushed regularly to the remote GitHub repository.
- **Task Transparency:** All tasks, user stories, and progress are tracked transparently through the GitHub Projects Kanban board to simulate an Agile/Scrumban workflow.
- **Quality Assurance:** Code must pass local unit tests (`pytest`) before being merged or finalized in the main branch.

## 2. Definition of Done (DoD)
A task, user story, or implementation item is considered "Done" when:
- **Code & Documentation:** The code is fully written, functional, and documented in Markdown files.
- **Version Control:** Changes are successfully committed and pushed to the remote GitHub repository.
- **Testing:** Unit tests (`pytest`) pass successfully without errors (applicable for Sprint 1 and beyond).
- **Review:** The deliverable satisfies the functional requirements and aligns with the initial Product Backlog.
